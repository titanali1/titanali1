# titanali — طراحی و دوخت (به‌سبک iOS 26 Liquid Glass)

تک‌فایل، بدون فریم‌ورک، بدون بیلد، بدون وابستگی شبکه: همه‌ی CSS و JS داخل `index.html` است.

**نسخهٔ ۴:** صفحهٔ اصلی = پروفایل + **فید به‌سایز واقعی اینستا** (استوری، پست ۴:۵ با ♥ لایک، 💬 کامنت، ⤓ دانلود، کاروسل چندتصویری، اتصال به پیج از Graph API) · **پنل ادمین ۱۵ تب با انتشار زنده روی فایل‌های هاست** · **ورود ادمین با نام کاربری/رمز** · مدیریت چند ادمین · **صندوق پیام‌ها با پاسخ مستقیم** · **پیوست فایل در گفتگو**. بخش‌های مهارت/موسیقی/پروژه‌ها و بقیهٔ کارت‌های صفحهٔ اصلی حذف شدند.

## ورود ادمین (پیش‌فرض)

```
نام کاربری: admin
رمز عبور : titanali1384
```

در کد، همین‌جا: `DEFAULTS.admins` (و تب «🔐 ادمین‌ها» در پنل برای افزودن/ویرایش/حذف ادمین).

> ⚠️ **این احراز هویت سمت کلاینت است.** فایل HTML عمومی است؛ هر کسی با دیدن کد، رمز را می‌بیند.
> برای محافظت واقعی: رمز را سمت سرور بررسی کنید (Workers/نمودار/Basic Auth) یا داده‌ها را در یک بک‌اند نگه دارید.

## اجرا

```bash
python3 -m http.server 8000      # یا index.html را مستقیم در مرورگر باز کنید
```

## فید اینستاگرام (سایز و چیدمان واقعیِ اینستا)

قاب تزئینی حذف شده؛ فید همان اندازه و ریتم پست اینستاگرام است (۴:۵، کپشن دو خط + «همهٔ توضیحات»، ردیف استوری، پاورقی).

- **نوار بالای فید**: آواتار + `@نام‌کاربری` + زیرنویس + وضعیت اتصال (🟢 فید از پیج متصل / ⚪ فید از محتوای خود سایت) + دکمهٔ **⟳ همگام‌سازی** + لینک پیج.
- **استوری‌ها**: نوار افقی؛ کلیک → نمایش تمام‌صفحه با نوار پیشرفت ۵ ثانیه‌ای، لمس چپ/راست برای عقب/جلو، Esc برای بستن، دیده‌شده‌ها خاکستری. آیکن «پیج» لینک واقعی پیج را باز می‌کند.
- **یک پست در هر نگاه** (مثل اینستا) + دکمهٔ «↓ پست‌های بیشتر»؛ کشیدن انگشت روی تصویر = اسلاید بعدی، دابل‌کلیک = ♥ (انیمیشن قلب)، لایت‌باکس برای دیدن تمام تصویر.
- **پست‌های خود سایت** (`D.gallery`): هر پست ♥ لایک، 💬 کامنت (۱۲ کامنت آخر)، ⤓ دانلود، ↗ اشتراک، شمارندهٔ «پسند · دانلود · تصویر» و ردیف پاورقی با زمان.
- **پست‌های واقعیِ پیج** (`D.ig.feed`): وقتی از سرور آیتم گرفته شود، همان پست با شمارنده‌های واقعی اینستا نمایش داده می‌شود؛ لایک/کامنت آن‌ها به پیج لینک می‌شود (اینستا اجازهٔ نوشتن از مرورگر نمی‌دهد).
- **همگام‌سازی**: پنل → تب «فید اینستاگرام» → «⟳ همگام‌سازی از سرور». سرور (`api.php?action=ig`) اول از **Meta Graph API** با توکن config می‌خواند و اگر توکن نبود، تلاش مستقیم (معمولاً CORS) را امتحان می‌کند؛ نتیجه در `D.ig.feed` ذخیره و روی هاست **منتشر** می‌شود، پس همهٔ بازدیدکننده‌ها همان را می‌بینند. «وارد کردن JSON» برای چسباندن خروجی Graph API هم هست.
- **اندازهٔ فید از پنل**: نسبت تصویر (۴:۵ · ۱:۱ · ۹:۱۶ · ۳:۴ · ۱۶:۹)، خط‌های کپشن، پست در هر نگاه، پخش خودکار با ثانیه، نمایش شمارنده‌ها و نوار استوری.

## پنل مدیریت — ویرایش همهٔ بخش‌های سایت

روی متن **`titanali`** بالای صفحه کلیک کنید (یا `Enter` پس از فوکوس) → فرم ورود ادمین (بدون هیچ راهنمای زیر فرم).
پنل یک **شیتِ سرمه‌ای تمام‌قد** است (روی دسکتاپ کارتِ گردِ 최대 `860px`، روی موبایل از پایین بالا می‌آید) با سربرگِ «پنل مدیریت + خوش‌آمدگویی + وضعیت»، دکمه‌های **مشاهده سایت** و **خروج**، **پیل‌های وضعیت** (اتصال سرور و `rev`، «● N منتشرنشده»، «✓ هم‌سان»، زمان آخرین انتشار، «♻ خودکار»، منبع فید) و **نوار تب قرصی** که تب فعال گرادیان آبی و درخشش دارد.
هر تب داخل یک **کارت** است: سربرگ با شکلک و نام بخش (+ تعداد ردیف‌ها) و بالای آن یک **جعبهٔ راهنمای آبی** که می‌گوید همان بخش کجا اعمال می‌شود. زیر سربرگ، **جست‌وجو** ردیف‌های همان تب را فیلتر می‌کند و تعداد نتیجه را نشان می‌دهد.
میان‌بُر: `Ctrl`/`Cmd` + `S` = ذخیره (وقتی پنل باز است).

۱۵ تب: **طرح‌ها 🖼 · دسته‌ها 🗂 · فید اینستاگرام 📸 · دکمه‌ها 🔘 · کارگاه 🧵 · متن‌های سایت ✍️ · 📥 صندوق پیام‌ها · 🚀 انتشار و هاست · ⚙️ تنظیمات · 🔐 ادمین‌ها · 🔄 همگام‌سازی سرور · 📊 آمار · 🏷 برچسب‌ها · ⚡ پرسش‌های سریع · 📞 تماس‌ها (JSON)**.

- **ابزار ردیف‌ها (روی همهٔ فهرست‌ها)**: هر کارت ردیف یک نوار ابزار دارد — `↑ ↓` جابه‌جایی، `⧉` دو‌نسخه، `★` (فقط طرح‌ها) بردن به ابتدای فید، `✕` حذف، و یک `«ویرایش دقیق این ردیف (JSON)»` که هر فیلدی را که فرم ندارد باز می‌کند (فقط اگر خودتان ویرایشش کنید اعمال می‌شود).
- **طرح‌ها** — 📷 انتخاب عکس از گالری گوشی یا آدرس تصویر، عنوان، دسته، توضیحات، «جدید»، چند تصویر برای یک پست، شمارندهٔ پسند/دانلود، حذف/افزودن. تصویر قبل از ذخیره به ۱۱۰۰px و JPEG ۸۵٪ فشرده می‌شود.
- **دسته‌ها** — نام + توضیح (بنر بالای گالری) + تصویر شاخه. حذف دسته، طرح‌ها را پاک نمی‌کند.
- **دکمه‌ها** — هر دکمهٔ ارتباطی (تلگرام، واتس‌اپ، ایمیل، تماس، وب‌سایت، اینستا، لین دلخواه) با فیلدهای برچسب/نوع/مقدار/آیکون/رنگ و **محل نمایش**: خانه، صفحهٔ ارتباط، بالای فرم گفتگو، همه‌جا، یا هیچ‌جا. دکمهٔ تازه (مثلاً بله/سروش/یوتیوب) = نوع «link» + آدرس.
- **متن‌های سایت** — هر متن رابط کاربری (منو، فید، گفتگو، ورود) با کلیدهای `nav.*`, `ig.*`, `cta.*`, `chat.*` … قابل عوض‌کردن است؛ خالی = بازگشت به پیش‌فرض همان زبان. متن دست‌نویس در `D.copy` ذخیره می‌شود و بر `I18N` اولویت دارد.
- **صندوق پیام‌ها** — پیام‌های کاربران (پیوست، بی‌پاسخ/پاسخ‌داده‌شده) و پاسخ مستقیم؛ پاسخ در گفتگو به‌صورت حباب «پاسخ کارگاه» می‌آید.
- **ادمین‌ها** — افزودن/ویرایش/حذف (ردّ نام تکراری، رمز زیر ۴ نویسه، حذف حساب خودتان یا آخرین ادمین). «🔑 رمز ادمین‌ها روی سرور» در تب همگام‌سازی.
- **انتشار و هاست** — وضعیت زندهٔ سرور (`state`): `rev`، چه کسی و کِی ذخیره کرده، فایل منتشرشده و اندازه‌اش، پیوست‌ها، صندوق، رویدادهای آخر؛ دکمه‌های «🚀 انتشار فوری · ↻ وضعیت · ⬇ گرفتن از سرور · ⬆ فرستادن کل داده · 🌐 بازخوانی» و کلید «انتشار خودکار پس از هر ذخیره».
- **JSON همه‌جا**: تب‌هایی که فرم ندارند (`stats`, `hobbies`, `contacts`, `quick`) با همان textarea ساختار آزاد در دسترس‌اند؛ خروجی/ورودی JSON و بازنشانی هم در نوار پایین پنل است.
- بدون بک‌اند، همه‌چیز در `localStorage` همان مرورگر می‌ماند؛ با `api.php` + «انتشار»، تغییرات روی فایل‌های هاست می‌نشیند (بخش بعدی).

## انتشار تغییرات روی هاست (پنل → فایل‌های public_html)

وقتی بک‌اند (`api.php`) نصب باشد، هر «💾 ذخیره» در پنل می‌تواند تغییرات را همان لحظه روی هاست بنشیند:

1. `POST api.php?action=publish` محتوا را در `titanali-data/content.json` می‌نویسد و `rev` را یک عدد بالا می‌برد.
2. همان‌جا یک **فایل ایستا** کنار `api.php` نوشته می‌شود: `titanali-content.json` (همان `data` + `social` + `rev` و `at`).
3. بازدیدکننده‌ای که `api.php` روی سرورش کار نمی‌کند (PHP خاموش/مسیر اشتباه) در ابتدای بارگذاری همان فایل را می‌خواند (`bakedPull`) و اگر `rev` تازه‌تر بود، سایت با محتوای منتشرشده باز می‌شود. اگر PHP کار کند، مسیر عادی `?action=content` (و کش ETag در `?action=baked`) استفاده می‌شود.
4. سرویس‌ورکر `titanali-content.json` را کش **نمی‌کند** (آدرس کوئری‌استرینگ دارد) و `.htaccess` برای آن `max-age=60, must-revalidate` می‌گذارد.

* **انتشار خودکار**: پیش‌فرض روشن است (تب تنظیمات یا تب انتشار). با خاموش‌کردنش، «ذخیره» فقط محلی می‌ماند و باید «🚀 انتشار روی هاست» را بزنید.
* **نوار نارنجی «● N تغییر منتشرنشده»** هر وقت `W` (فرم باز پنل) با `D` (دادهٔ ذخیره‌شده) فرق داشته باشد بالا می‌آید و سه کار دارد: انتشار، خواندن وضعیت، برگرداندن تغییرات منتشرنشده.
* **تعارض نسخه**: اگر سرور `rev` بالاتری داشته باشد، `publish` با ۴۰۹ رد می‌کند و پنل «⬇ گرفتن از سرور» را پیشنهاد می‌کند؛ بازنویسی اجباری همان «⬆ فرستادن کل داده» است.
* **کنترل از config** (`titanali-config.php`): `'publishFile' => 'titanali-content.json'` (یا `''` برای خاموش)، `'publishMax' => 2000000`.
* **از خط فرمان** (بی‌نیاز از مرورگر): `POST api.php?action=publish` با `{"data":…}` و توکن نشست در هدر `X-TA-Token`.

## بک‌اند اختیاری روی سرور (`api.php`) — صندوق مشترک و همگام‌سازی محتوا

سایت همچنان تک‌فایل و استاتیک است؛ این لایه **اختیاری** است. اگر `api.php` کنار `index.html` باشد، سایت خودش آن را می‌شناسد و این‌ها مشترک می‌شود؛ اگر نباشد، همه‌چیز دقیقاً مثل قبل فقط در `localStorage` می‌ماند:

| چه چیزی | بدون بک‌اند | با بک‌اند |
|---|---|---|
| محتوا (طرح‌ها، دسته‌ها، پروفایل، تنظیمات) | همین مرورگر | روی سرور + کش محلی، با شمارهٔ نسخه (`rev`) |
| لایک / دانلود / بازدید | شمارندهٔ محلی | شمارندهٔ مشترک سراسری (رویکرد `overlay`) |
| کامنت زیر پست‌ها | محلی | مشترک، با حذف توسط ادمین |
| پیام کاربر و پاسخ کارگاه | محلی (شبیه‌سازی‌شده) | صندوق مشترک؛ پاسخ ادمین در گفتگوی همان کاربر می‌نشیند |
| پیوست گفتگو | Data URL در همان مرورگر | فایل روی سرور (`titanali-data/uploads`) با نام هَش‌شده |
| ورود ادمین | `DEFAULTS.admins` در سورس | bcrypt روی سرور + توکن ۱۲ ساعته |

### نصب (سه قدم)
1. `api.php` را کنار `index.html` در `public_html` بگذارید (در بستهٔ زیپ هست). پوشهٔ `titanali-data/` خودکار ساخته و با `.htaccess` + `index.php` خاموش بسته می‌شود.
2. سایت را باز کنید → روی عنوان **titanali** بالا کلیک کنید → وارد پنل شوید → تب **«🔄 همگام‌سازی سرور»**.
3. فرم «نصب روی سرور» را پر کنید (نام کاربری ۳+، رمز **۸+**) → «ساخت ادمین سرور و فرستادن محتوا». از این پس ورود با رمز سرور بررسی می‌شود و اگر سرور قطع باشد، فهرست محلی امتحان می‌شود.

> جای امن‌تر برای دیتا: بیرون از `public_html`. فایل `titanali-config.sample.php` را به `titanali-config.php` تغییر نام دهید و `dataDir` را ست کنید (نمونه: `dirname(__DIR__).'/titanali-data'`).

### امنیت و محدودیت‌ها
- هش رمز با `password_hash` (bcrypt) و مقایسه با `password_verify`؛ **هیچ رمزی در پاسخ سرور برنمی‌گردد**.
- توکن ۲۰ بایت تصادفی، هَش‌شده در `tokens.json`، عمر ۱۲ ساعت؛ از هدر `X-TA-Token` خوانده می‌شود (نه کوکی → CSRF بی‌اثر). حذف ادمین، توکنش را می‌سوزاند.
- محدودیت نرخ: ورود ۱۰ بار/۱۰دقیقه برای هر IP+کاربر، ارسال پیام ۱۲/دقیقه، کامنت ۶/دقیقه، آپلود مهمان ۱۲/۱۰دقیقه، نصب ۵/۱۰دقیقه.
- متن‌ها `strip_tags` + حذف کنترل‌کاراکتر + سقف طولی؛ فیلد زنبورعسل (`company`) هر ربات را بی‌صدا رد می‌کند.
- سقف حجم: ۶ مگابایت JSON و ۶ مگابایت پیوست؛ مهمان فقط `jpeg/png/webp` می‌فرستد؛ پیوست‌ها فقط از راه `?action=file&f=` سرو می‌شوند (mime از فهرست سفید، `basename` و regex روی نام، `Content-Security-Policy: default-src 'none'`).
- نوشتن با `flock` + `tmp → rename` اتمی؛ خطاها JSON با کد وضعیت درست؛ `display_errors` خاموش.
- `Cache-Control: no-store` روی پاسخ‌ها و سرویس‌ورکر `*.php` را میان‌گیری نمی‌کند. فایل‌های `?action=file` یک‌ساله کش می‌شوند چون نامشان با محتوا عوض می‌شود.
- **هنوز نمانده اینجا:** رمز `DEFAULTS.admins` برای حالت آفلاین در سورس است (تا سایت بدون سرور هم کار کند)؛ اعلان لحظه‌ای به ادمین نیست (بین ۴۵ ثانیه یک‌بار پرس‌وجو می‌شود)؛ پیام‌ها و کامنت‌ها فقط در فایل‌های JSON سرورند (دیتابیس ندارند).

| تب همگام‌سازی می‌گوید «سرور پیدا نشد» | `api.php` جایش نیست، PHP خاموش است، یا هاست فایل را با پسوند php اجرا نمی‌کند. `api.php?action=health` را مستقیم باز کنید: باید JSON بدهد |
| پاسخ HTML/متن خام | PHP اجرا نمی‌شود (روی برخی هاست‌ها `AddHandler` لازم است) — سایت خودبه‌خود به حالت محلی برمی‌گردد |
| «پوشهٔ سرور نوشتنی نیست» | مجوز `titanali-data` را ۷۷۵ و مالکیت را روی کاربر PHP (معمولاً `nobody`/`user`) بگذارید؛ یا `dataDir` را بیرون ببرید |
| ۴۰۹ / «تعارض نسخه» | کسی دیگر از یک دستگاه دیگر ذخیره کرده: «⬇ گرفتن از سرور» یا «⬆ فرستادن محتوا» (بازنویسی) |
| ۴۲۹ | محدود نرخ — چند دقیقه صبر |
| ۴۰ | حجم پیوست بیشتر از سقف |
| ۴۲۳ | `api.php` هست ولی ادمینی نصب نشده — فرم نصب را پر کنید |
| ۴۰۳ روی خود `api.php` | `mod_security` هاست؛ با هاستینگ باز کنید یا `X-TA-Token` را به `?t=` تغییر دهید (پشتیبانی شده) |

### حذف بک‌اند
`api.php` (و اگر خواستید `titanali-data/`) را پاک کنید: سایت بدون هیچ تغییری به همان حالت تک‌فایل/محلی برمی‌گردد. برای بازگشت محتوا از سرور به دست: `?action=export` یا دکمهٔ «🧾 خروجی کامل».

### عیب‌یابی سریع در کنسول مرورگر
`window.titanali` خواندنی است: `titanali.API` (وضعیت، `rev`، `conflict`)، `titanali.D`، `titanali.likeCount(0)`، `titanali.apiRefresh()`، `titanali.apiPush(false)`، `titanali.apiThreads()`.

## استقرار روی هاست سی‌پنل (cPanel)

> **راهنمای کامل سی‌پنل** (آپلود، دامنه، SSL، PHP و INI، مجوزها، نصب بک‌اند، کش، بکاپ، امنیت، عیب‌یابی، چک‌لیست انتشار) در
> **[CPANEL.md](CPANEL.md)** است. بخش پایین خلاصهٔ همان است.

سایت ایستا (static) است: **PHP و دیتابیس لازم نیست**، فقط Apache/LiteSpeed (بک‌اند `api.php` اختیاری است — بخش بالا).
ریشهٔ مخزن دقیقاً همان محتوای `public_html` است:

```
index.html          ← کل سایت (HTML + CSS + JS در یک فایل)
.htaccess           ← gzip، کش، هدرهای امنیتی، ۴۰، نوع MIME، بستن فایل‌های سرویس
sw.js               ← سرویس‌ورکر (آفلاین + به‌روزرسانی شبکه‌اول برای صفحه)
site.webmanifest    ← نصب‌شدن به‌عنوان اپ (RTL/fa)
favicon.svg · apple-touch-icon.png · icon-192.png · icon-512.png · maskable-512.png
og.png              ← پیش‌نمایش لینک در تلگرام/واتساپ/اینستا
404.html · robots.txt · sitemap.xml
deploy/files/          ← قالب‌های .htaccess و sw.js و 404/robots/sitemap
deploy/make-cpanel.py  ← سازندهٔ بسته و تصاویر (python3 deploy/make-cpanel.py)
```

> فایل‌های متنی ریشه با هر بار اجرای اسکریپت از `deploy/files/` کپی می‌شوند؛ پس تغییر دائمی را همان‌جا بدهید (نه فقط در ریشه).

```bash
gh release create v1.0.0 titanali-cpanel.zip titanali-cpanel.zip.sha256 \

```

> اگر زیپ را داخل `public_html` استخراج می‌کنید، بعد از استخراج همان زیپ (و پوشهٔ `deploy/`) را پاک کنید؛ در `.htaccess` با `FilesMatch` رد می‌شوند، ولی تمیزتر است.

### روش ۱ — زیپ (سریع‌ترین)
```bash
python3 deploy/make-cpanel.py      # dist/titanali-cpanel.zip
```
1. cPanel → **File Manager** → `public_html`
2. **Upload** → `dist/titanali-cpanel.zip` → راست‌کلیک → **Extract** (تیک «Overwrite existing files»)
3. زیپ و پوشهٔ `deploy/` را از `public_html` **پاک کنید** (`.htaccess` آن‌ها را رد می‌کند، ولی تمیزتر است)

### روش ۲ — FTP
با FileZilla (SFTP/FTP-SSL) فایل‌های ریشه را مستقیم داخل `public_html` بفرستید.

### دامنه و SSL
- **SSL/TLS Status → Run AutoSSL** (یا Let's Encrypt) را بزنید؛ `.htaccess` جابه‌جایی `http → https` را انجام می‌دهد.
- **سرویس‌ورکر فقط روی HTTPS** ثبت می‌شود؛ روی `http://ip` یا تست محلی بی‌اثر است (عمدًا).
- در **Domains → titanali1.ir** مطمئن شوید `Document root` به `public_html` می‌خورد و `www` هم نام‌های جایگزین دارد.
- `canonical` و لینک‌های OG روی `https://titanali1.ir/` تنظیم شده‌اند. اگر دامنه فرق کرد، این دو خط و `SITE` در `deploy/make-cpanel.py` و `robots.txt`/`sitemap.xml` را عوض کنید.

### در زیرپوشه (مثلاً `titanali1.ir/site/`)
همه‌ی مسیرها نسبی‌اند (`./sw.js`، `./site.webmanifest`)، پس بدون تغییر کار می‌کند؛ فقط اگر خطای ۴۰۴ روی `sw.js` دیدید، `RewriteBase /` را در `.htaccess` به `RewriteBase /site/` عوض کنید.

### اگر بعد از آپلود ۵۰۰ گرفتم
روی برخی هاست‌های LiteSpeed ماژول‌ها فعال نیستند. به‌ترتیب این بلوک‌ها را در `.htaccess` کامنت کنید تا خطا رفع شود:
`mod_brotli` ← معمولاً اول‌ین متهم · سپس بلوک `Content-Security-Policy` (اگر اسکریپت بیرونی اضافه کردید) · سپس `ExpiresByType`.
بستهٔ امنِ بدون ریسک: فقط `AddDefaultCharset`, `DirectoryIndex`, `Options -Indexes`, `mod_deflate`.

### آپدیت سایت
1. `index.html` را ویرایش کنید → `python3 deploy/make-cpanel.py` → زیپ تازه را Extract کنید.
2. چون `index.html` با `max-age=0, must-revalidate` سرو می‌شود و سرویس‌ورکر «شبکه‌اول» است، visitors نسخهٔ تازه را می‌بینند. برای اطمینان، در `deploy/files/sw.js` شمارهٔ نسخه را بالا ببرید: `const V='titanali-v2'` (کش‌های قدیمی خودکار پاک می‌شوند).

### داده‌ی ادمین و هاست
- بدون بک‌اند، محتوای پنل مدیریت در `localStorage` **همان مرورگر** می‌ماند؛ با `api.php` + «🚀 انتشار» روی فایل‌های هاست می‌نشیند. برای انتقال محتوا بین دستگاه‌ها: «⬇ خروجی JSON» را بگیرید و در دستگاه مقصد «⬆ ورودی JSON» بزنید — یا `DEFAULTS` را در `index.html` ویرایش و deploy کنید (روش توصیه‌شده برای محتوای دائمی).
- برای فید واقعی اینستاگرام توکن Graph API را در `titanali-config.php` بگذارید (`igToken` و `igGraphId`)؛ بدون آن فید از محتوای خود سایت ساخته می‌شود و باز هم با «انتشار» روی هاست می‌نشیند (جزئیات: `CPANEL.md` §۹-پ).
- پس از هر «ذخیره» در پنل (با انتشار خودکار) فایل ایستای `titanali-content.json` کنار `api.php` نوشته می‌شود؛ سایتِ بدونِ PHP هم همان را می‌خواند (§۹-ب در `CPANEL.md`).
- اگر برای پنل مدیریت محافظت واقعی می‌خواهید: cPanel → **Directory Privacy (Password Protect)** را روی یک پوشهٔ جدا برای فایل‌های ادمین بگذارید (یادتان باشد اگر کل `public_html` را قفل کنید، سایت برای همه قفل می‌شود).

## نصب روی هاست — دو لینک مستقیم

**۱) یک خط در Terminal سی‌پنل** (بکاپ می‌گیرد، بسته را می‌ریزد، مجوزها را تنظیم می‌کند، داده را بیرون `public_html` می‌برد و ادمین سرور را می‌سازد):

```bash
curl -fsSL https://raw.githubusercontent.com/titanali1/titanali1/latest/deploy/install-on-server.sh | bash
```

بدون پرس‌وگرم و برای CI: `SITE=https://titanali1.ir TA_ADMIN_USER=admin TA_ADMIN_PASS='…' SKIP_INSTALL=0 bash install-on-server.sh` — گزینه‌ها: `PUB`، `MOVE_DATA=0`، `SKIP_INSTALL=1`، `YES=1`، `ZIP_FILE=…`، `REF=v1.0.2`.

**۲) نصب‌کنندهٔ وب داخل بسته** — اگر Terminal ندارید: بسته را در `public_html` Extract کنید و سپس باز کنید:

```
https://titanali1.ir/titanali-install.php
```

اول وضعیت را بررسی می‌کند (فایل‌های بسته، PHP، نوشتن، پوشهٔ داده، تازگی `index.html`)، بعد ادمین سرور را از راه `api.php` می‌سازد (bcrypt سمت سرور)، `titanali-config.php` را می‌نویسد و **خودش را پاک می‌کند**. تا وقتی ادمینی نباشد کار می‌کند، nonce یک‌بارمصرف و سقف ۶ تلاش در ساعت دارد، و رمز را در هیچ جا نمی‌نویسد. اگر خودش پاک نشد، صفحه دستور `rm` را نشان می‌دهد — حتماً پاکش کنید.
